# 1.9.19 — Architecture review export

## What changed

- Added `agentic architecture-report <run-id> [--json] [--output <dir>]`.
- The command exports `reports/architecture-review.md` and `reports/architecture-review.json` inside the run state directory by default.
- Architecture reports aggregate synthesized specialist analysis plus independent post-implementation review findings.
- Architecture findings can now carry `group`, `currentDesign`, `why`, `impact`, `priority`, `ownerDomain`, and `principle`.
- The architecture specialist now declares a coverage matrix across 13 architecture concerns, including an e-commerce-specific area that can be marked not applicable.
- Missing coverage is reported as `not-reviewed`; it is never silently treated as pass.
- Finding synthesis preserves the architecture-report metadata when duplicate specialist findings are collapsed.

## Compatibility

The schema additions are backward-compatible for non-architecture specialists. Existing runs can still be exported; older architecture artifacts without an explicit coverage matrix will show coverage gaps instead of fabricated passes.

New architecture artifacts are stricter: the architect must cover all required areas and must provide the richer rationale fields on every architecture finding.

## Validation

```bash
npm run workflow:architecture-report:selftest
npm run workflow:artifacts:check
npm run workflow:check
```
