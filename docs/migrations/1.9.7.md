# Migration to 1.9.7

No action required unless you have customised `ai/subagents/contracts.yaml` or a mobile-evidence prompt.

## The runtime writes mobile evidence; the agent no longer does

The `mobile-evidence` role is `read_only` and never had permission to write, so it could not produce the artifact it is defined to output:

```text
✗ Appium execution returned, but evidence validation failed:
- .../device/mobile-device-qc.md was not created/updated by this attempt
- .../device/screenshots has no fresh screenshot from this attempt
```

Now:

- the role returns its QC report as its response, and the runtime saves it as `device/mobile-device-qc.md`;
- a fenced ```json block in that response becomes `device/appium-sessions.json`;
- screenshots are written by the runtime when the agent asks for one:

```bash
node ai/tasks/feature/mobile-evidence.js capture FEAT-001 --platform ios --name 01-launch
```

Captures are refused unless an attempt is in progress, and a name that is not `[A-Za-z0-9][A-Za-z0-9-]*` is rejected, so nothing can be written outside the run's own screenshot directory.

If you wrote your own prompt for this role, stop telling it to write files and point it at the capture command instead.

## mobile-evidence may build the app

Its contract gains `test_execute`, so it can run `flutter build`, `gradlew` or `xcodebuild` to produce the installable artifact device QC needs. It still has no `product_write`.
