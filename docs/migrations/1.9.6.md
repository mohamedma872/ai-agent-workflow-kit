# Migration to 1.9.6

No action required. No state, artifact or configuration format changes.

## An executor that runs out of credits now falls back instead of stopping the run

A role configured with a fallback executor:

```yaml
implementation:
  executor: codex
  fallback: [claude]
  execution:
    retry_on: [timeout, transient, unavailable]
```

used to stop the whole run when its primary executor hit a usage limit:

```text
✗ implementation/implementation: codex exited 1
```

The limit was classified `deterministic`, which is not retryable, so the fallback never ran. Usage limits, exhausted credits and billing stops are now `unavailable`, so attempt 2 goes to the next candidate executor.

If you deliberately want a run to stop rather than switch agents when the primary executor is exhausted, remove `unavailable` from that role's `retry_on` in `ai/workflows/feature.yaml`.

## Failures say what the agent actually reported

A failing executor's reason is read out of its event stream and written to stderr:

```text
codex: usage_limit_exceeded: You've hit your usage limit.
✗ implementation/implementation: codex exited 1
```

Previously only the second line appeared and the reason had to be dug out of the agent's own session log.
