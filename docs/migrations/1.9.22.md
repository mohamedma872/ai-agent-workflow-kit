# 1.9.22 — MASVS-categorized security review and audit mode

Runtime 1.9.22 changes the security specialists' instructions and adds eval cases. It does not change the workflow, routing, guard rules or artifact schemas.

## What changes for you

- `security-reviewer` reports now have two extra columns, **MASVS group** and **origin** (`new`, `changed`, `pre-existing`), and two extra sections, **Coverage** and **Disclosure**.
- When findings are written as JSON, the group and origin are in `tags`, for example `["masvs:MASVS-STORAGE", "origin:new"]`. `tags` already existed in `subagent-finding-v1`, so stored artifacts stay valid.
- You can ask for a full-codebase audit:

  ```text
  Use the security-reviewer agent in audit mode on this repository, base branch origin/main.
  ```

  Audits cover the Dart/JS layer and the native Android and iOS projects separately, and give one verdict for the change and one for the codebase.

## Action required

None. If you copied `security-reviewer.md` or `security-analyst.md` into a project and edited them, merge the new **Categories**, **Checklist** and **Report** sections by hand.

## Evals

Five new `security` subagent cases are in `ai/tasks/subagent/cases.yaml`. Run them from a plain terminal (live Claude evals refuse to run inside a Claude Code session):

```bash
node ai/evals/run.js subagent run --case security-webview-host-prefix-token --agent claude
```

Results recorded before 1.9.22 used the previous prompt; compare by prompt hash.
