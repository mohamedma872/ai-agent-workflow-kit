# 1.9.33 — Pinned Flutter, analyzer baseline, deletion guard

Runtime 1.9.33 adds `ai/workflow/analyzer-baseline.js`, pin detection in `ai/workflow/toolchain.js` (`flutterPin`), a mass-deletion check in `ai/workflow/tracked-files.js`, the `analyzer_baseline` input for `qa-execute` and `orchestration`, a `flutter:pin` doctor check, and more `gh pr` subcommands in the agent capability guard. Stages, gates, routing and artifact formats are unchanged.

## What changes for you

- **Install the pinned Flutter SDK if you have one.** When `.fvmrc` pins a version that is installed (`fvm install <version>`), every role runs on it. When it is not installed, the engine warns once and `agentic doctor` shows `flutter:pin` as incompatible; roles are told to avoid re-resolving packages.
- **Build + Tests and Final Verification get an analyzer comparison** with the run's base, in `engine/analyzer-baseline.md`. It costs a few seconds to a minute (18 s for 36 files in a real run) and needs `.dart_tool/package_config.json` in the worktree.
- **A role that deletes 25 or more tracked files fails**, with the files restored. Raise `AI_WORKFLOW_MAX_DELETED_FILES` before `agentic retry` when a large deletion is intended.
- **Agents cannot approve, review, comment on, close or lock pull requests.** Do that yourself.

## Action required

None. For Flutter projects with `.fvmrc`, run `agentic doctor` and install the pinned SDK it names.
