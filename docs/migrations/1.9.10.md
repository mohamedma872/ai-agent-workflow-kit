# Migration to 1.9.10

No action required. One guard rule became more precise; nothing else changed.

## Quoted arguments are data, not shell syntax

A command that mentions a guarded path and contains `>` or `->` *inside a quoted argument* is no longer treated as rewriting that path:

```bash
# allowed now; asked before
node ai/workflow/refactor-checkpoints.js record R1 W0 \
  --diff "..." --test "null self-check: mutant fails -> Some tests failed"
```

Real redirects still ask, including to a quoted target:

```bash
echo broken > ai/guard.yaml        # ask
cat tmp.yaml >> ai/agents.yaml     # ask
echo broken > "ai/guard.yaml"      # ask
```

And code passed to an interpreter is still scanned in full, because there the quotes hold code:

```bash
node -e "require('fs').writeFileSync('ai/guard.yaml', '{}')"   # ask
```

If a behavior-preserving refactor previously failed with `refactor implementation missing verified checkpoint(s)` while the agent reported that the guard blocked its checkpoint command, retry the stage:

```bash
agentic retry <run-id> implementation
```
