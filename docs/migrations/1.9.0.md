# Migration to 1.9.0

No action required. Runtime 1.9.0 fixes two false reports for Flutter projects; no workflow, artifact or state formats changed.

## Flutter SDK installed but not on PATH

Before:

```text
✗ flutter    required missing    flutter not found
  → Install Flutter SDK and add flutter to PATH
```

After, with the SDK unpacked at `~/develop/flutter`:

```text
✓ flutter        required available     Flutter 3.47.5 at ~/develop/flutter
! flutter:path   optional incompatible  ~/develop/flutter/bin is not on PATH; agentic adds it for
                                        its own runs, but flutter commands you run yourself will fail
  → export PATH="/Users/you/develop/flutter/bin:$PATH"  # add to ~/.zshrc
```

Searched locations: `FLUTTER_ROOT`, `~/develop/flutter`, `~/flutter`, `~/sdk/flutter`, `~/Development/flutter`, `~/src/flutter`, `~/fvm/default` and `~/fvm/versions/*`, `~/.puro/envs/*/flutter`, `~/Library/flutter`, `~/Applications/flutter`, `~/tools/flutter`, and `/opt/homebrew`, `/usr/local`, `/opt`.

`agentic` exports the SDK's `bin` directory on PATH for its own runs only; your shell is not modified. Run the `export` line above to fix it everywhere.

## Flutter projects are not web frontends

A Flutter app has a `web/` directory as a build target, which previously made the runtime treat it as a JavaScript frontend:

- the doctor reported `frontend:build-script` and `frontend:test-script` as missing and looked for a package manager;
- the subagent selector added the web `frontend` specialist to Flutter features.

A web app directory (`frontend/`, `web/`, `apps/web/`) now counts only when it contains its own `package.json`, so a real JS app in a monorepo still routes to the frontend specialists while Flutter's build output does not.
