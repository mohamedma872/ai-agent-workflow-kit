# 1.9.24 — Encryption, key storage and integrity checks in the security review

Runtime 1.9.24 extends the `security-reviewer` checklist and adds eval cases. Workflow, routing, guard rules and artifact schemas are unchanged.

## What changes for you

Security reviews now check and report, explicitly:

- the cipher and mode of local encryption, and whether it detects tampering;
- where data keys live (Keystore TEE/StrongBox, Keychain accessibility, Secure Enclave) and whether hardware-backed storage is warranted;
- iOS Data Protection classes and Android storage locations;
- unsigned remote config, client-computed money values and payment status, and idempotency of order and payment calls;
- the hosts the app talks to and a pinning decision;
- app and device attestation.

The Coverage section names the cipher mode, key storage, hosts and pinning decision that were verified, so a reader can tell these were looked at.

## Action required

None. If you copied `security-reviewer.md` into a project and edited it, merge the new checklist items by hand.

## Evals

Six new `security` cases in `ai/tasks/subagent/cases.yaml`. Run them from a plain terminal (live Claude evals refuse to run inside a Claude Code session):

```bash
node ai/evals/run.js subagent run --case security-cbc-without-mac --agent claude
```
