# Migration to 1.9.3

No action required. State, artifact and workflow formats are unchanged. Everything here came out of driving a real `/feature` run to completion against a Flutter application.

## Security: the architecture gate could be skipped by any caller

1.9.1 let the engine skip `architecture-selection` when the transition's `executor` was `workflow-engine`. That value is just an argument, so anyone — including an agent — could pass it and step over the gate in a whole-app refactor, where choosing an architecture is the human's decision.

The skip now requires both the engine executor **and** that the stage does not apply to this run (its `when: whole_app_refactor` condition is false). A normal feature run still skips the stage automatically; a real whole-app refactor still stops for the human.

## `agentic retry` now actually retries

It reset statuses but left the recorded attempts, so the next resume hit:

```text
✗ build-test/qa-execute: last failure type deterministic is not retryable
```

Spent attempts for whatever is being retried are now cleared as well.

## New: send a stage back for rework

```bash
agentic retry FEAT-001 implementation
```

Tests failing after implementation is ordinary. Before, only failed stages could be retried, so `build-test` re-ran against unchanged code and failed identically every time. Naming a stage resets it even though it passed. `approval` and `architecture-selection` refuse:

```text
✗ approval is a human gate and cannot be reset; re-approve it instead
```

## New: seeing and resolving specialist conflicts

Unresolved conflicts block the plan stage. There was no CLI path to them at all, and the records held only finding ids.

```bash
agentic conflicts FEAT-001
agentic resolve FEAT-001 CONFLICT-001 --decision "..." --rationale "..." [--owner NAME]
```

The listing shows each side of the disagreement — agent, severity, title, recommendation — so the decision can be made from the terminal. A pair of findings that disagree under several tags is now one conflict rather than one per tag.

## Diagnosing a rejected artifact

When an agent's structured artifact fails validation, its raw output is kept at `engine/<stage>-<role>.rejected` and the path is named in the error. It used to be deleted, which made a genuinely failing build indistinguishable from malformed output.
