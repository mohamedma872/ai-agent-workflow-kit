# Migration to 1.9.4

No action required, but read this if your project's `.agentic/knowledge.yaml` uses `include` or `exclude` and you rely on the `security` or `security-review` roles for review coverage.

## `security`/`security-review` retrieval is no longer scoped by the project's own config

1.9.2 wired `.agentic/knowledge.yaml`'s `include`/`exclude` globs into Hybrid RAG retrieval for every role. That introduced a blind spot: the file being reviewed could narrow or exclude the exact files a security reviewer most needs to see — accidentally, if `include` was scoped to a subset of the codebase for noise reduction, or in principle deliberately, if the repository itself were compromised.

As of 1.9.4, the `security` and `security-review` roles ignore `include`/`exclude` entirely and always retrieve from the full corpus (still minus `ai/rag/hybrid-rag.js`'s built-in ignore list — `node_modules`, `build`, `.git`, `.agentic-runs`, etc. — and its sensitive-file patterns, which were never retrievable to begin with). `prioritize` is unaffected and still applies to these roles, since a relevance boost can only surface files higher in the ranking — it can't remove anything from consideration.

If your project's `include` list is scoped to a subset of the repository (e.g. `src/**` only, for a large monorepo), the security roles will now see retrieval results from outside that scope too. This is intentional: it trades some extra retrieval noise for the security reviewer against the alternative of a reviewer that can be silently scoped out of the code it's meant to examine.

No config change is needed to get this — it's automatic based on the role name.
