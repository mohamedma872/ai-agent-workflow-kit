# Migration to 1.5.2

Runtime 1.5.2 fixes a macOS standalone-CLI self-test failure and tightens stable update semantics.

## macOS updater fix

On macOS, temporary paths can be presented through aliases such as:

```text
/var/...
/private/var/...
```

Git may return the canonical path while Node initially sees the alias path. Runtime 1.5.1 compared those strings directly, so the post-update standalone CLI self-test could incorrectly report:

```text
agentic init must run at a Git repository root
```

Runtime 1.5.2 canonicalizes existing project paths before comparing repository roots.

## Stable update behavior

`agentic update` now treats a newer runtime SemVer as the update signal.

A newer commit on `main` with the same runtime version (for example README-only documentation changes) no longer causes a full reinstall and verification cycle.

```bash
agentic update --check
agentic update
```

JSON status also reports `sourceDiffers` separately from `updateAvailable`.

## Recovery from the 1.5.1 failure

If a 1.5.1 update attempt rolled back after the macOS self-test error, no project source was changed. Once 1.5.2 is available, run:

```bash
agentic update
```

The 1.5.1 updater will fetch the 1.5.2 source first; verification then runs using the fixed 1.5.2 CLI self-test.
