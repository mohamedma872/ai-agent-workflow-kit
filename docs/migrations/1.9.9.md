# Migration to 1.9.9

One new workflow stage. No state or configuration format changes.

## `conflict-arbitration` runs between analysis and plan

Specialists analyse independently and never see each other, so none of them could ever declare a disagreement and the conflict gate never fired. A new read-only role now reads every specialist finding and declares the material conflicts:

```text
analysis → conflict-arbitration → plan
```

This adds one agent call per run. Its artifact is `05-analysis/arbitration.md` with a `05-analysis/arbitration.json` sidecar, and unresolved conflicts block the plan exactly as documented:

```bash
agentic conflicts <run-id>
agentic resolve <run-id> CONFLICT-001 --decision "..." --rationale "..."
```

Runs started before this release have no arbitration artifact; their conflict set stays empty, which is the behaviour they already had. To arbitrate an existing run, retry the stage:

```bash
agentic retry <run-id> conflict-arbitration
```

If you maintain your own workflow YAML, add the role and stage and change `plan`'s `needs` from `[analysis]` to `[conflict-arbitration]`.

## A blocked specialist is recorded instead of discarded

A `subagent-findings` artifact with `status: blocked` is now valid, provided it carries at least one finding explaining the blocker. The role is marked blocked and the run stops for a human with the findings intact. Resume with `agentic retry <run-id> <role>` once the blocker is addressed.

## Named Structurizr workspaces validate

If a whole-app refactor previously failed at `c4-model` with "expected a Structurizr DSL workspace" while the agent had produced a named workspace, retry that stage:

```bash
agentic retry <run-id> c4-model
```
