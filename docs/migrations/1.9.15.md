# Migration to 1.9.15

No action required.

## `requires_changes` on a role

A role that must modify the product can now say so:

```yaml
implementation:
  executor: codex
  fallback: [claude]
  requires_changes: true
```

If that role exits cleanly with an untouched worktree, the attempt is recorded as `unavailable` and the next candidate executor runs. Both tracked edits and new untracked files count as changes.

Only set it where an empty diff is genuinely wrong. `fixes` does not set it, because "no change needed" is a valid conclusion for that stage.

## Blocking reviews are kept

A review with an unresolved critical/high finding is now written to `09-reviews/` before the stage fails, so the findings are available to `fixes` and to a retried implementation:

```text
✗ review reports unresolved findings (recorded at ios-review.md):
  - $.findings: 1 unresolved critical/high finding(s)
```

The gate is unchanged: the stage still fails and the run still cannot reach verification. Only the artifact survives.
