# Migration to 1.9.16

No action required. Spec publishing is off until a project turns it on.

## Turning it on

```yaml
# .agentic/config.yaml
specs:
  enabled: true
  dir: specs        # default
```

From then on, a run that reaches verification writes:

```text
specs/<run-id>/README.md               index, with the original request
specs/<run-id>/requirements.md
specs/<run-id>/acceptance-criteria.md
specs/<run-id>/definition-of-done.md
```

These are committed with the change, unlike `.agentic-runs/`, which stays ignored.

## Backfilling runs you already have

```bash
agentic spec publish FEAT-001
agentic spec list
```

## What later runs see

Roles that declare `existing_specs` — `orchestration`, which owns requirements, acceptance criteria, definition of done and the plan — receive every published spec as context, so a change to the same capability extends the agreed specification instead of restating it.

Turning the block off, or removing it, stops both the writing and the reading.
