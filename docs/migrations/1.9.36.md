# 1.9.36 — Quota failures are free, criteria settle conflicts, resolve resumes, agents run without your plugins

Runtime 1.9.36 changes `ai/workflow/execution-policy.js`, `ai/workflow/engine.js`, `ai/workflow/conflict-tracker.js`, `ai/workflow/conflicts.js`, `ai/workflow/artifacts.js`, `ai/workflow/router.js` and `ai/cli/agentic.js`. The `conflict-arbitration` schema gets two optional fields (`settledBy`, `prevails`), and the `conflict-arbitration` role's purpose in `ai/workflows/feature.yaml` says when to use them.

## What changes for you

- **Fewer manual retries when codex is out of quota.** A usage-limit, not-installed or wrote-nothing attempt no longer counts against `max_attempts`. The fallback gets the role's whole budget, so one transient error from claude no longer stops `implementation` or `fixes`. Recorded attempts are unchanged: the free attempt still appears in `state.json` with `exitType: unavailable`.
- **One quota hit per machine, not per stage.** `.agentic-runs/_executor-limits.json` records the limit until the executor's reset time (or an hour). Other runs go straight to the fallback until then. Delete the file to try the executor again sooner.
- **Conflicts settled by your criteria do not wait for you.** When the arbitrator cites acceptance criteria, definition-of-done items or earlier decisions that decide a conflict, and every cited id exists in the run's own artifacts, the conflict is recorded as resolved by `criteria`. `agentic conflicts <id>` shows it and the command to decide otherwise; the plan you approve cites it like any other decision. To overrule one, resolve it before the plan runs, or rework the plan (`agentic retry <id> plan`) and resolve it then.
- **`agentic resolve` no longer needs `agentic resume`.** Deciding the last open conflict resumes the run in the background (`▸ resuming <id>… engine pid N · log …`). A script that relied on resolve returning without starting the engine adds `--no-resume`; `--wait` keeps the engine in the foreground. Its output is now a readable line instead of the JSON entry; `node ai/workflow/conflicts.js resolve` called directly, outside the CLI, still prints the JSON.
- **Engine agents run without your Claude Code plugins.** Plugins enabled in `~/.claude/settings.json`, the project's `.claude/settings.json` or `.claude/settings.local.json` are switched off for engine-launched claude agents. Hooks in those files, such as a personal guard hook, still run. Set `AI_WORKFLOW_USER_PLUGINS=1` if a role relied on a plugin.

## Action required

None. Restart any `agentic progress` window and any engine started before the upgrade: a process left running keeps the old code.
