# 1.9.23 — Platform reviewer checklists

Runtime 1.9.23 rewrites the `flutter-reviewer`, `android-reviewer` and `ios-reviewer` instructions and adds eval cases. Workflow, routing, guard rules and artifact schemas are unchanged.

## What changes for you

- The three reviewers return a fixed report: Verdict, a Findings table with **category** and **origin** (`new`, `changed`, `pre-existing`) columns, Strengths, and a Coverage line per category. An unreviewed category is `not-reviewed`, never a pass.
- Each reviewer has severity anchors. A version or build number that goes backwards, a build that fails on a clean checkout, or a launch crash is **critical** and blocks the merge.
- You can ask for a full audit instead of a diff review, for example:

  ```text
  Use the ios-reviewer agent in audit mode on ios/, base branch origin/main, production branch origin/master.
  ```

- The reviewers now declare read-only tools (`Read, Grep, Glob, Bash`), matching `security-reviewer`.

## Action required

None. If you copied any of the three files into a project and edited them, merge the new **Checklist**, **Severity anchors** and **Report** sections by hand.

## Evals

Seven new cases in `ai/tasks/subagent/cases.yaml` (`ios-review-*`, `android-review-*`, `flutter-review-*`). Run them from a plain terminal; live Claude evals refuse to run inside a Claude Code session:

```bash
node ai/evals/run.js subagent run --case ios-review-version-regression --agent claude
```
