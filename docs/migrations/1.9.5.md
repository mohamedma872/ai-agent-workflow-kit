# Migration to 1.9.5

No action required unless your project's `.agentic/guardrails.yaml` has been hand-edited.

## `.agentic/guardrails.yaml` is now enforced (tighten-only)

Until 1.9.4 this file was documentation-of-intent only; nothing read it. As of 1.9.5 the guard engine loads it from the project root on every tool call, alongside the runtime's `ai/guard.yaml` and task packs:

| Field | Effect |
|---|---|
| `secret_files` | Extra files the model never reads (Read → deny, shell dump → deny) |
| `guarded_files` | Extra files only a human changes (Edit/Write or shell rewrite → ask) |
| `evidence` | Directories treated as an audit trail — `rm` inside → deny |
| `shell_rules` | Extra `ask`/`deny` shell rules, matched by `regex` (+ `flags`) or `contains` |
| `project.*` | Informational; these guarantees are always on |

The pack is **tighten-only**. A shell rule with any decision other than `ask` or `deny` (for example `allow` or `off`) is ignored. A project file can add protection but can never loosen a runtime rule, so the pack is safe to load from ordinary, unprotected project content. `.agentic/guardrails.yaml` itself is always guarded: an agent editing it asks the user first.

### What to check

- A project whose file is still the untouched 1.9.4-or-earlier template: nothing changes. The old template only has the `project:` booleans, which stay informational.
- A project whose file was hand-edited with `secret_files`/`guarded_files`/`evidence`/`shell_rules` expecting them to work: they now take effect. Run `agentic guard check` to validate the file; it flags any rule that will be ignored.
- To see everything that is active for a project, run `agentic guard explain`.

`agentic init` only writes missing files. To get the new commented template, delete `.agentic/guardrails.yaml` and re-run `agentic init`.
