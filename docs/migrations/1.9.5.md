# Migration to 1.9.5

No action required. State gains one optional field (`lastFailures`); nothing else changes.

## Rework no longer stalls on the stage that caused it

```bash
agentic retry FEAT-001 implementation
```

1.9.3 reset `implementation`, but `build-test` — the stage whose failure prompted the rework — kept its spent attempts, so the resume stopped straight away:

```text
✗ build-test/qa-execute: last failure type deterministic is not retryable
```

Stages after the reworked one that are failed, blocked or stuck are now reset with their attempts cleared. Stages that passed keep their result, and `approval` / `architecture-selection` are never reset.

## Agents are told what went wrong

A retried or reworked role received no information about the failure it was supposed to fix. Role prompts now begin with:

```text
## Previous failures to address

These are recorded failures from this run. Fix the cause named here rather than re-doing the same work.

- previous build-test/qa-execute failure: ...
- build-test/qa-execute (pending): tests await real dart:io inside fake-async
- build-test-qa-execute.rejected (rejected output excerpt): ...
```

It carries the role's own last failure, any failed or blocked stage's note, and an excerpt of the rejected artifact from `engine/<stage>-<role>.rejected`.

Because clearing attempts is what allows the work to run again, the last reason per stage/role is preserved separately as `state.lastFailures` so the feedback outlives the reset.
