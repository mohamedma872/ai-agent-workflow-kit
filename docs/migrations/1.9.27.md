# 1.9.27 — Body shapes and logged-client inventory in the security review

Runtime 1.9.27 extends the `security-reviewer` checklist and report and adds eval cases. Workflow, routing, guard rules and artifact schemas are unchanged.

## What changes for you

Security reviews now:

- **Trace every body shape through the scrubber.** One sensitive value per shape is followed through the real interceptor and redaction code:
  - maps;
  - JSON strings the caller already encoded, which `jsonEncode` in the interceptor escapes again;
  - form-encoded strings and `FormData`;
  - bytes and streams.
- **List every logged client.** A new `Logged clients` table shows each client with a logging, crash-reporter or network-monitor interceptor, the sensitive fields it sends or receives, the body shapes, and whether redaction is proven. It is required in audit mode, and in diff-review when the change touches a client, interceptor or scrubber.
- **Check the pattern, not just the reported call.** When a fix moves one sensitive call to an unlogged client, the other clients are checked for the same data.
- **Re-check redaction findings strictly.** One is fixed only when every body shape comes out redacted. Adding keys to a deny-list is not enough.

## Action required

None. If you copied `security-reviewer.md` into a project and edited it, merge the new checklist items, the `Logged clients` report section and the re-check rule by hand.

## Evals

Three new `security` cases in `ai/tasks/subagent/cases.yaml`. Run them from a plain terminal (live Claude evals refuse to run inside a Claude Code session):

```bash
node ai/evals/run.js subagent run --case security-log-scrubber-string-body --agent claude
```
