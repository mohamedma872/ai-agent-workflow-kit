# 1.9.32 — See what each agent is doing

Runtime 1.9.32 adds `ai/workflow/role-activity.js`, a `stream_command` for Claude in `ai/agents.yaml`, `router.js exec --activity-file`, the dashboard's `d` key and details pane, `agentic progress --details`, `agentic activity`, and a "needs you" banner for verified runs with no pull request recorded. Workflow stages, gates, executor routing, the retry policy and the artifact formats are unchanged.

## What changes for you

- **The dashboard describes every role** in a dimmed line under it, and shows what a running role is doing now (`↳ Read lib/… · 4s ago`). Press `d` for the details pane (each running agent's last actions); `esc` goes back.
- **`agentic activity <run-id> [role] --follow`** prints the same feed in a plain terminal.
- **Roles now run with Claude's streaming output.** The engine asks for an activity file, so `claude -p` runs with `--output-format stream-json --verbose` instead of `--output-format json`. The artifact, cost and exit status are read from the stream's final result line, as before. A project that overrides the `claude` entry in `ai/agents.yaml` without a `stream_command` keeps its own command; it gets start/finish lines but no per-action activity.
- **New files per role:** `<run>/engine/<stage>-<role>.activity.jsonl` (and `.prev.jsonl` after a large file rotates). They hold one short, redacted line per action, never tool output or file contents. Delete them freely; they are only read for display.
- **Verified runs with no PR recorded** (verified before 1.9.31, or with a PR opened by hand) now show `⚠ Verified — no pull request recorded yet → agentic pr <id>`. Run `agentic pr <id> --dry-run` first: it names the base it would use (pass `--base <branch>` when the worktree recorded none), and the real run reuses an open PR from the run branch instead of opening another.

- **A stopped stage explains itself.** When an agent's report was rejected, the banner shows its own summary, tests, failed checks and the files its tools changed, plus options (revert, read the report, leave a note, retry). `agentic why <run-id>` prints everything.
- **`<run>/notes/<stage>.md`** is new: what you write there is given to every role of that stage on its next attempt.
- **Read-only roles leave tracked files as they found them.** The engine restores any tracked file their tools changed (an implicit `pub get` rewriting `pubspec.lock`, Xcode rewriting `project.pbxproj`) and records it in `engine/<stage>-<role>.restored.json`. You no longer revert those by hand.

## Action required

None. Runs in progress pick it up at their next role. Roles that ran before the upgrade have no activity file and show `(no activity recorded yet)`.
