# Migration to 1.9.2

No action required, but read this if you already have a `.agentic/` directory: some fields in `.agentic/config.yaml` and `.agentic/knowledge.yaml` now actually do something, and existing projects don't get the new template comments automatically (`agentic init` only writes a file if it's missing).

## `.agentic/config.yaml` and `.agentic/knowledge.yaml` were previously decorative

`agentic init` has always generated `.agentic/config.yaml`, `knowledge.yaml`, and `guardrails.yaml`, but nothing in the runtime ever read them back — every field was a no-op. If you'd already hand-edited `rag.top_k` or `knowledge.yaml`'s `include`/`exclude` expecting them to change retrieval behavior, they didn't.

As of 1.9.2, these fields are read on every retrieval call:

- **`config.yaml` → `rag.enabled`**: `false` disables Hybrid RAG context for every specialist role in the project — a hard kill switch that overrides any role-specific retrieval setting.
- **`config.yaml` → `rag.mode`**: `hybrid` (default) or `off`; any other value behaves like `off`.
- **`config.yaml` → `rag.top_k`** / **`rag.context_budget`**: override `ai/subagents/contracts.yaml`'s global retrieval defaults for this project.
- **`knowledge.yaml` → `include`**: if non-empty, only files matching one of these globs are retrieval candidates. This *narrows* scope — it does not add file types outside `ai/rag/hybrid-rag.js`'s own extension/basename list.
- **`knowledge.yaml` → `exclude`**: extra exclusions on top of the built-in ignore list (`node_modules`, `build`, `.git`, `.agentic-runs`, `.ai-worktrees`, `.dart_tool`, etc.).
- **`knowledge.yaml` → `prioritize`**: chunks whose source path matches one of these globs get a small relevance-score boost.

If your existing `.agentic/knowledge.yaml` still has the default `include` list generated by an older `agentic init` (`src/**`, `app/**`, `lib/**`, `android/**`, `ios/**`, `docs/**`, `tests/**`, `test/**`, `api/**`), retrieval will now be scoped to just those directories — previously it covered the whole repository (minus the ignore list). If your product code lives somewhere else, add it to `include`, or delete the `include:` key entirely to retrieve from anywhere (like before).

## Still not enforced — and that's deliberate

`config.yaml`'s `workflow.require_plan_approval` / `require_architecture_selection`, and all of `guardrails.yaml`, remain documentation-of-intent only. Wiring these in naively would mean an ordinary, unprotected project file could disable the plan-approval human gate or other fence guarantees just by being edited — that's a real weakening of the runtime's core guarantee, not a convenience. If you need to change gate structure, edit `ai/workflows/feature.yaml` or `ai/guard.yaml` directly — both are protected files that only a human changes.

## Getting the new template comments on an existing project

`agentic init` is idempotent and only writes a file if it's missing, so re-running it on an existing project won't refresh the comments in your current `.agentic/*.yaml`. Either delete a file and re-run `agentic init` to regenerate it with the new template (safe for `knowledge.yaml`/`guardrails.yaml`; back up `config.yaml` first if you've customized it), or just read the field-by-field table in [README § Configuration](../../README.md#configuration).
