# 1.9.20 — Clean engineering standards

## What changed

Runtime 1.9.20 adds a provider-independent `clean-engineering` standards pack based on paraphrased principles from:

- Robert C. Martin — *Clean Code*
- Robert C. Martin — *Clean Architecture*
- Martin Fowler — *Refactoring*
- Martin Fowler — *Patterns of Enterprise Application Architecture*

The pack covers naming/readability, functions, responsibilities, SOLID, dependency direction, architectural boundaries, state ownership, error handling, concurrency, comments/documentation, testing, refactoring discipline, code smells, simplicity, severity, and review restraint.

## Where it is enforced

The workflow router injects the standard directly into selected role prompts, so the same rules reach Claude or Codex:

- architect
- architecture assessment/options/target/migration
- architecture compliance review
- implementation
- fixes
- code review
- behavior regression review

This is stronger than a Claude-only `.claude/rules` file because executor routing can change per project.

## Review behavior

The standards are heuristics, not dogma:

- repository evidence is required;
- approved ADRs and explicit constraints may justify deviations;
- style preference alone cannot become a blocking finding;
- code smells are investigation triggers, not automatic defects;
- an abstraction must justify its complexity;
- dependency direction and ownership matter more than folder names.

## Compatibility

No project configuration change is required. Existing projects receive the standard after updating the runtime.

## Validation

```bash
npm run workflow:check
npm run agentic:selftest
```
