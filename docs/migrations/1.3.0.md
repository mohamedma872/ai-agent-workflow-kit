# Migration to 1.3.0

Runtime 1.3.0 adds **Hybrid RAG context retrieval** for repository-reading workflow agents. Existing feature, refactor, architecture, guardrail, and verification commands remain compatible.

## What changes

Repository-reading roles now receive a focused evidence pack generated from the current request and repository instead of relying only on the fixed run artifacts already listed in their contract.

The built-in retrieval channels are:

- keyword/BM25-style relevance
- lexical-vector similarity
- exact symbol matching
- path/metadata relevance
- exact phrase matching
- role-aware hints
- optional semantic-embedding similarity

Retrieved items keep source path, line range, channel scores, and excerpts.

## Persisted evidence

Per-role retrieval results are written under:

```text
ai/runs/<run-id>/engine/rag-context/<stage>-<role>.json
```

These files are runtime evidence and remain under the existing ignored run directory.

## Security behavior

The retriever excludes common secret-bearing files including environment files, credentials/secrets, private keys, keystores, and platform service credential files.

Retrieved content is treated as untrusted repository evidence. It must not override workflow instructions or guardrails.

## Manual verification

```bash
npm run workflow:rag:selftest
npm run workflow:rag -- --query "authentication architecture" --role architect
```

## Semantic embeddings

No embedding provider is required for 1.3.0. Local hybrid retrieval works without network access. The retriever exposes a provider-neutral semantic scoring channel that participates in reranking when a semantic index and query embedding are supplied programmatically.
