# 1.9.28 — Security eval cases run against security-reviewer

Runtime 1.9.28 changes the eval catalog and the subagent eval adapter. Agents, workflow, routing, guard rules and artifact schemas are unchanged.

## What changes for you

- The `security` subagent eval cases in `ai/tasks/subagent/cases.yaml` now use `role: security-review`, which resolves to `security-reviewer`.
- Before this release, `role: security` resolved to `security-analyst`, the pre-implementation threat-model agent. So changes to the `security-reviewer` checklist were not measured by these cases.
- Live runs and metrics for these cases are now reported under the `security-review` role. Earlier `security` results are not directly comparable.
- The subagent eval adapter now accepts output wrapped in a Markdown code fence. Before, a correct answer in a fence was recorded as a harness error ("nothing gradable").
- `security-analyst` has no eval cases left. `hillclimb.js init` needs at least 4 cases per agent, so tuning `security-analyst` needs new threat-model cases first.

## Action required

- If you added your own cases with `role: security` to test a review, change them to `role: security-review`. Keep `role: security` only for threat-model cases.
- If you have a saved hillclimb state for `security-analyst` from before 1.9.28, start a new one. Its case IDs now resolve to `security-reviewer`, so resuming it would score the wrong agent.

## Evals

```bash
node ai/evals/run.js subagent run --case security-token-logged --agent claude
```
