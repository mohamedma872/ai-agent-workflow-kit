# Migration to 1.9.1

No action required. Runtime 1.9.1 fixes three bugs (a stalled `/feature` run, rejected specialist artifacts, and an unindexed-noise RAG bug) and adds a `retry` command and a dashboard column; no workflow, artifact or state formats changed.

## Every non-refactor `/feature` run stalled at `architecture-selection`

`architecture-assessment`, `architecture-options`, `architecture-selection`, and the rest of the architecture stages only apply to a whole-app behavior-preserving refactor (`when: whole_app_refactor` in `ai/workflows/feature.yaml`). On any normal feature run the engine correctly decided to skip them — except `architecture-selection`, which `runs.js` also treats as a human gate that only `architecture-select` may move. The engine's own skip transition hit that same guard and was rejected, so the run stopped with:

```text
architecture-selection: architecture-selection is a human gate; use runs.js architecture-select <id> <option-id>
```

on every run, refactor or not. The human-gate check now makes an exception for the engine's own skip (executor `workflow-engine`); a person still cannot skip or force it manually.

If a run is stuck on this, `agentic resume <run-id>` picks it back up — no state repair needed.

## Specialist analysis and review artifacts were rejected

Any `subagent-findings` artifact (every analysis role, and any review role that used the same schema) failed validation with a wall of single-character "errors," because the code that renders its Markdown table lived inside the function that is supposed to return an array of error strings, and returned a rendered Markdown string instead — which then got spread character-by-character into the error list. Analysis and review roles now complete normally; the Markdown renderer lives in `renderMarkdown`, where every other schema's renderer already lived. `validateArtifactData` also now throws immediately if any future `semanticProblems` branch returns something other than an array, instead of silently corrupting validation.

## New: `agentic retry <run-id> [role...]`

When one or more analysis/review roles fail or get blocked, you no longer need to hand-edit `state.json`. `agentic retry <run-id> architect security` resets just those roles to `pending` and resumes; `agentic retry <run-id>` with no roles resets every failed/blocked role (and any stuck non-parallel phase) at once. Roles that already passed are left alone.

## Hybrid RAG no longer indexes runtime/build directories

`.agentic-runs/`, `.ai-worktrees/`, and `.dart_tool/` are now in the ignore list alongside `node_modules`, `build`, `.gradle`, etc. Previously, retrieval for an external project could surface stale run state, isolated worktree copies of the product under review, or Flutter's generated `.dart_tool/` output as if they were the actual product source.

## `agentic runs` shows a FEATURE column

`agentic runs` / `agentic runs --all` list each run's real title next to its id:

```text
  RUN      FEATURE                        PROG  STATE      CURRENT           UPDATED
▸ FEAT-001 Offline sync for the inbox      42%   approved   analysis          3m ago
```

Title text comes from the first non-empty line of the run's `00-request.md`; a run without one shows `—`.
