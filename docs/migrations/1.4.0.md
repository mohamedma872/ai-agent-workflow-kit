# Migration to 1.4.0

Runtime 1.4.0 adds the first standalone `agentic` CLI and separates the installed runtime from the repository being changed.

Existing npm-script workflows inside this repository remain supported.

## New standalone model

A standalone invocation uses four different locations:

```text
runtime root   installed Agentic Workflow runtime
project root   user's existing Git repository
product root   isolated .ai-worktrees/<run-id> worktree
state root     user's .agentic-runs/
```

The runtime source is not copied into the application's source tree and is not an Android/iOS/web/backend production dependency.

## Initialize a project

From an existing Git repository:

```bash
agentic init
agentic doctor
```

Initialization creates lightweight development-only configuration:

```text
.agentic/
  config.yaml
  knowledge.yaml
  guardrails.yaml
  README.md

.codex/hooks.json
```

It also gitignores:

```text
.agentic-runs/
.ai-worktrees/
```

Claude receives the standalone guard adapter through a runtime-owned session settings file. It does not require copying the runtime's Claude settings into the project.

## Feature workflow

```bash
agentic feature FEAT-001 --request "Add biometric login"
agentic progress FEAT-001 --watch
agentic approve FEAT-001
```

## Refactors

```bash
agentic refactor RF-001 --request "Refactor auth without changing behavior"
agentic approve RF-001

agentic refactor-app APP-001 --request "Modernize the whole application architecture without behavior changes"
agentic architecture APP-001 B
agentic approve APP-001
```

## Hybrid RAG

```bash
agentic rag --query "Where is the refresh token stored?" --role security
```

Hybrid RAG reads the selected project/worktree, while retrieval evidence is stored with the run state.

## Human gates

`agentic approve` and `agentic architecture` are human-only commands. Runtime guardrails reject attempts by an executing coding agent to invoke those commands.

## Compatibility

When `AI_WORKFLOW_PROJECT_ROOT` / `AI_WORKFLOW_STATE_ROOT` are not set, existing in-repository commands continue to use the legacy `ai/runs/` state location. This preserves the current development and CI workflow for this repository.
