# Migration to 1.9.11

No action required. Two guard rules became more precise and one became stricter.

## Upgrade from 1.9.10 promptly

1.9.10 let three interpreter forms through that had been caught before it:

```bash
bash -lc "echo bad > ai/guard.yaml"     # allowed in 1.9.10, asks again now
sh -xc   "echo bad > ai/guard.yaml"     # same
node -p  "require('fs').writeFileSync('ai/guard.yaml', '{}')"
```

## Stricter than any previous release

Python and Ruby write idioms were never detected. They are now:

```bash
python3 -c "open('ai/guard.yaml','w').write('')"   # asks
ruby -e "File.write('ai/guard.yaml','')"            # asks
```

If a project keeps its own `write_indicators`, add `".write("` to it.

## Read-only roles can capture output again

`2>&1` duplicates a descriptor and writes nothing, so it no longer counts as a mutation:

```bash
flutter test 2>&1 | tail -5    # allowed for a read-only role
flutter test > out.txt         # still denied
```

If a verification stage previously failed with definition-of-done items marked `blocked` because the role could not re-run tests, retry it:

```bash
agentic retry <run-id> verification
```
