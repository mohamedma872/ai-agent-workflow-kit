# 1.9.25 — Man-in-the-middle and root/jailbreak checks in the security review

Runtime 1.9.25 extends the `security-reviewer` checklist and adds eval cases. Workflow, routing, guard rules and artifact schemas are unchanged.

## What changes for you

Security reviews now report:

- **A trust table per traffic path:** Dart, native SDKs and WebViews, each with:
  - the CA store it trusts;
  - whether a user CA is trusted;
  - whether ATS or `network_security_config` applies;
  - whether certificate transparency is enforced.
- **MITM scenarios ranked for your app.** The review says plainly that pinning does not stop a device owner with root or Frida.
- **Root, jailbreak and runtime tampering:** what the app detects, how it responds, what a rooted-device owner can do, and the release hardening (R8, Dart obfuscation, no `debuggable`).
- **Pinning kill switches** are checked: they must not come from unsigned remote config, and a signed flag needs an expiry and anti-rollback version.

## Action required

None. If you copied `security-reviewer.md` into a project and edited it, merge the new checklist items by hand.

## Evals

Four new `security` cases in `ai/tasks/subagent/cases.yaml`. Run them from a plain terminal (live Claude evals refuse to run inside a Claude Code session):

```bash
node ai/evals/run.js subagent run --case security-user-ca-trusted-in-release --agent claude
```
